## Phase 2：实际修改

- `versions/task-state.mjs`：分别投影健康检查和模型工作流；不修改原始对象。展示 request/task/session/run/audit/handoff、模型与调用声明、工具版本、输入哈希、数据日期、资金版本、审批过期时间及原始服务端审计。
- `versions/task-client.mjs`：超时、取消等待、状态码、格式异常、请求/任务编号一致性；Web Locks 跨标签页互斥；仅保存结果未知请求的编号/路径/时间；不保存金融输入。未知结果不自动重试，存储或锁能力缺失时停止提交。
- `versions/task-view.mjs` / `.css`：两个现有页面共用一个任务观察组件，支持查询、切换、刷新恢复、历史失效提示和键盘访问。数据未知显示 NOT_PROVIDED / UNKNOWN。
- `investment.html/js`：保留偏好、持仓、Quant 报表和视觉；修复不存在的 workspace 链接；接入统一任务证据；输入变化后旧结论失效。
- `risk-workbench.html/js`：移除浏览器填写 reviewer/approver、Risk 决策、审批和模拟执行的代码；保留三个带具体原因的禁用按钮。新分析显式为 REVIEW_ONLY/PAPER、使用现有 idempotency_key。能力路由不可用时不开放模型入口。
- `server.js`：**只在静态文件白名单增加四个 UI 文件**。未改 `/api`、Owner Bridge、审批、Risk、资金或审计逻辑。
- `scripts/ui-demo-p0*`：前端专项单元、浏览器、真实本地 Demo、录制脚本；`review/` 为本轮验收证据。
- 没有修改 `core/`、`tools/`、`merchant/`、`data/` 或其他 Owner 的运行源码。未修改正式部署或公共 Schema。

回执校验需要服务端返回 SIMULATED/PAPER 语义下的 SIMULATION_ONLY、execution_allowed=false、同一 task/execution/proposal hash、有效 completed_at 和 side_effects=false。只读任务、缺少回执、版本/编号不一致均不显示模拟完成；无论服务端状态为何，此 UI 都不提供执行动作。
