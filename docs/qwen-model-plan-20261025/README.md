## 这轮改了什么

1. **接入不靠猜。**候选配置只接受北京业务空间专属地址、指定模型、JSON 规划和明确关闭的思考开关。错误地址、其他地域、未验证配置会被拦下。
2. **费用直接用人民币计算。**新增人民币单价字段，避免把人民币价格再乘美元汇率。历史美元配置和已有账本继续兼容；同一模型混填两种币种会报错。
3. **先预留，再调用。**按本次输入上界、输出上限和最多两次尝试动态预留。只有完整响应、单次调用、用量一致且在上界内才降低预留；缺失用量、失败尝试或中断按保守金额记账。
4. **失败不会包装成成功。**识别百炼欠费错误 `Arrearage`、HTTP 402、429、超时、意外思考内容和截断。不会自动启用备用模型，也不会因模型重试重复保存持仓或做金融操作。
5. **把证据留下。**日志记录模型、请求编号、尝试次数、用量、人民币估算标记和关闭思考的配置；费用回执不保存密钥、原始持仓或完整提示词。

入口仍为 `createModelGateway()`。没有修改 Risk 判定、Memory 规则、人工确认、确定性金融计算、数据隔离或网页 UI；新增集成测试确认这些约束仍然生效。原生模型 `tool_calls` 仍被拒绝，业务工具继续由 Core 的既有受控流程调用。

2026-10-25 核查的北京官方目录价：每百万输入 Token **¥0.8**、每百万输出 Token **¥2.7**。[官方价格页](https://help.aliyun.com/zh/model-studio/model-pricing)。这是目录价，不是账户余额；不把缓存优惠或免费额度预先算作可用预算。

计算公式：`预计人民币费用 = (输入 Token × 0.8 + 输出 Token × 2.7) ÷ 1,000,000`。内部以百万分之一元记账，合计后向上取整；人民币价格不再乘汇率。

| 情况 | 预计金额 | 含义 |
| --- | --- | --- |
| 单次输入 1,000、输出 100 Token | ¥0.001070 | 本地用量结算案例 |
| 一轮规划与回答合计输入 4,000、输出 1,000 Token | ¥0.005900 | 仅举例，不代表每轮固定用量 |
| 上述用量连续 1,000 轮 | ¥5.90 | 不含重试、其他服务及基础设施费用 |

一轮用户任务通常有“规划”和“回答”两次模型请求，上表的单请求上界不能当作整轮上界；两次都到上界时合计预留 ¥0.127900。原有每日与总预算闸门继续约束所有请求。此前建议的 staging 总额 ¥1、每日 ¥0.50 **不是本次批准的支出**，模板也没有据此开启收费调用。

## 以后接通真实 API 的步骤

现在可以继续看代码与本地证据，不需要把密钥发给任何人。实际接通前按以下顺序完成：

1. 在百炼开通北京业务空间，确认该空间可使用 `qwen3.8-flash`，复制 API Host；查看余额和实际单价。此前在聊天中出现过的密钥，应先去服务商后台轮换。
2. 确认能管理**交接包目标账户中的** `personal-ai-fund-chat-staging` 及其 Risk 服务。旧 `personal-ai-fund-manager-core-agent` 是另一套 Worker，不能把服务名当成 Secret 名称，也不能擅自部署到另一个账户冒充原 staging。此前交接记录里的权限缺口本轮未重新查验。
3. 确认独立 staging 的调用次数及总／每日费用上限后，将密钥存入该 Worker 的 Secret `LLM_A_API_KEY`，填写专属地址和人民币配置。使用 [关闭状态的配置模板](../../chenchen/integration/public-chat/providers.qwen.env.example)。不要整段复制通用 A/B 模板，更不要把密钥写入 `vars`。
4. 在单独批准的有限测试窗口中，先验证协议与计费用量，再启用相应验证标记。真实用量可能推翻当前保守 Token 上界，未核实前不能标记为已验收。依次检查中文规划、业务工具、SSE、Risk、402／429／超时、重复请求和回执；保存脱敏真实响应编号及后台扣费对账。
5. staging 联合验收通过后另行申请生产发布。现有生产服务、账本和预算不因本地测试通过而自动切换。
